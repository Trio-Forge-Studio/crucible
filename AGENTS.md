# Agent instructions

Crucible is Trio Forge's roblox-ts game framework. It replaces Flamework and will own the game runtime. This repository currently proves the package layout with placeholders. Do not add framework features as part of scaffold maintenance.

## Layout

- `packages/crucible` is the single runtime package, `@trioforge/crucible`.
- `packages/crucible/src/index.ts` is the shared-safe root. It must never import or re-export server or client code, including through transitive imports.
- `packages/crucible/src/server/index.ts` and `src/client/index.ts` are the side entries. Physical `server` and `client` folders in the package resolve these entries for roblox-ts 3.0.0. Keep them alongside the package exports map. An exports-only remap does not resolve with this compiler.
- `examples/sample-game` imports the root and each side entry through workspace dependencies. Its Rojo project maps the runtime under `ReplicatedStorage.rbxts_include.node_modules.@trioforge`.
- `docs` holds the user guides, one plain Markdown topic per file. The `crucible` binary embeds them, and `crucible docs <topic>` prints one. Each topic starts with `# Title`, a blank line, and a one-line summary that ends with a period. Document only what the code exports today. `test/docs.test.mjs` type-checks every `ts`, `typescript`, and `tsx` block against the runtime package.
- `test` holds Lune specs. `.lune/test.luau` uses the `@trioforge/tooling` runner. The specs load the built place through roblox-ts's runtime and assert subpath resolution and root isolation.
- `packages/compiler-types` is `@trioforge/compiler-types`, a private copy of `@rbxts/compiler-types` whose iterator types take the three parameters TypeScript 7 requires. The `tsconfig.ts7.json` files beside the runtime and sample configs use it, and `test/compiler-types.test.mjs` checks them with tsrs. The real configs stay on TypeScript 5 while `rbxtsc` builds them.
- `cli/crates/compiler` is `crucible-compiler`, the TypeScript 7 compiler in `design/compiler.md`. It checks a tsconfig with tsrs, fills a fact table, and lowers each file to Luau from the syntax tree and the facts alone. tsrs types stay in its `program`, `extract` and `tree` modules. `cargo run -p crucible-compiler --example compile -- <tsconfig> <out>` writes the Luau, and `crucible build` still uses `rbxtsc`. Its tests read `packages/crucible/out`, so run `pnpm build` first. The test that runs the emitted Luau needs `lune` on PATH and is ignored by default, so run it with `cargo test -p crucible-compiler -- --ignored`.
- `cli` is the `crucible` command line, a separate Cargo workspace. `crucible oc` calls Roblox Open Cloud and keeps the JSON-document and exit-code contract in `docs/oc.md`. `cli/spec/registry.json` is generated by `cargo xtask spec build`. Do not edit it by hand.

## Checks

Run `pnpm install --pm-on-fail=download` and `rokit install`. Keep the lockfile after dependency changes. Rokit pins the Roblox tools, and the root `rust-toolchain.toml` pins Rust to the version the pinned tsrs SHA requires. CI installs Rust from that file. Vite+ configures TypeScript lint and formatting in `vite.config.ts`.

Run `pnpm check` before calling a change complete. It must exit 0. It checks formatting and lint, compiles the runtime, builds the sample into `build/sample-game.rbxl` with `crucible build` through `cargo run`, and runs the Lune specs. `pnpm fmt` fixes TypeScript, configuration, and Luau formatting. Fix failures at their cause.

For changes under `cli`, run `pnpm build` from the repository root before the npm package test. Also run `cargo fmt --all --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo xtask spec check`, `cargo test --workspace`, and `node --test npm/package.test.mjs` from `cli`. CI runs them on Ubuntu and Windows.

The Lune loader supplies only the engine behavior needed to execute the sample imports. A passing Lune spec does not prove gameplay behavior in Studio.

## Conventions

- Use Conventional Commits with a scope, such as `chore(repo): scaffold the workspace`.
- Name branches `<type>/<short-description>` and open PRs into `main`.
- A PR that resolves a Linear issue puts `Closes <ID>` in its body, such as `Closes CRU-12`. Branch names carry no issue ID, so the body links the PR to the issue.
- Push with an explicit refspec, such as `git push origin HEAD:refs/heads/chore/scaffold`.
- The pre-commit hook runs staged checks, and the pre-push hook refuses pushes to `main`; `pnpm install` installs both.
- Use squash merge and delete the branch after merge. Do not merge without task authorization.
- Comment only a non-obvious reason that the code cannot express.
- The runtime and CLI use MIT. Publish npm packages only through the tag release workflow. Publishing a release, creating secrets, pushing release tags, and changing repository settings require separate authorization.
